# LANE EP — measure the precision of the one unchecked model decider in the harness: `scripts/rob2_build.py::_match` accepts a registry outcome as the review's outcome when `embed.rank(a,[b])` cosine ≥ 0.45, and nothing checks it afterwards. It decides which registry record feeds risk-of-bias. Report `n of N` correct, by hand adjudication, with every pair listed so a human can re-check. Do not change the threshold or the code.

Report file: `LANE-EP-REPORT.md`. Base `ad5e7c66`. No network. Read `harness/embed.py` (pinned MiniLM-L6-v2, cache `cache/embeddings.json` — replay must not need the model; if a pair is not cached, record `EMBEDDING_NOT_CACHED` and do not load the model unless it is vendored locally and `allow_model` is the module's default), `scripts/rob2_build.py`, `harness/rob2.py`, `cache/<slug>/rob2.json` for all 32 topics.

## What to measure
1. **Enumerate every decision the threshold made on this base**: for each of the 32 topics, every (review primary-outcome name, registry outcome title) pair `rob2_build` compared, its cosine, and the decision (`match` ≥ 0.45 / `no match`). Where `rob2.json` records the chosen registry outcome, reconstruct the pair from it; where it does not, re-run the enumeration path in `rob2_build` with the model disabled (`allow_model=False`) and report `n pairs with cached vectors of N pairs`. N is the denominator; name it.
2. **Adjudicate by hand every pair** (you read both strings and the review's registered outcome definition from `protocols/<slug>.md`): `SAME_OUTCOME` / `DIFFERENT_OUTCOME` / `AMBIGUOUS` with one line of reason each. A registry outcome that is a broader composite, a different timepoint, a subgroup, or a different construct (kidney-specific vs cardiorenal; CV death + HF hospitalisation vs worsening HF incl. urgent visits) is `DIFFERENT_OUTCOME`.
3. **Confusion table at 0.45**: true match, false match (accepted but DIFFERENT — the dangerous cell: a wrong registry record feeding RoB), missed match (rejected but SAME), true reject; precision and recall with their counts, `n of N`, AMBIGUOUS reported separately and never counted as correct. Also report the same table at 0.35, 0.55, 0.65 so the threshold's sensitivity is visible. Quote every false-match pair verbatim with its cosine.
4. **Consequence trace**: for every false match, which page's RoB table / D5 / low-risk sensitivity consumed the wrong registry outcome on `ad5e7c66` (`docs/reviews/<slug>/review.json → rob2`, `rob_sensitivity`, `grade`). `n pages whose RoB rests on a false match of 32`.
5. **Do not fix.** Write the measurement as `docs/embedding_decider_precision.json` (pairs, cosines, adjudications, tables) and `tests/test_embedding_decider_precision.py` that reads the JSON and asserts the measured precision is recorded (a plant that fails if the JSON is absent or the false-match list is not enumerated) — so the number cannot be quoted without its evidence. Recommendation section: keep as candidate generator with a deterministic component-set post-check, or replace under the reproducible-model contract (`REPRODUCIBLE_MODEL_CONTRACT.md` in your clone root if present).

Every number MEASURED; `n of N` with N named; a 100% is a defect report unless the instrument is shown to fail on a planted DIFFERENT pair (plant one synthetic pair with cosine above threshold that is obviously a different outcome and show the table counts it as a false match).
