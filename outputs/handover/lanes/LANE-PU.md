# LANE PU — publication records are not trials: trial-unit language, the served inclusion/exclusion status of specific records, and the spironolactone scope drift

Report file: `LANE-PU-REPORT.md`.

## The failures (measured on served pages at aa8ed28a)

1. **Publication records leaking into trial-unit language.** `colchicine-secondary-cv-prevention` says "26 further screened-in trial(s) had no poolable value" / the STALE banner lists "32407460, 41670023, 41605493, 40263680, 39189611, 39166327, and 19 more" as eligible trials not pooled. Several of those records are SECONDARY or ECONOMIC publications of trials already represented in the pool (COLCOT PMID 31733140, LoDoCo2 32865380, CLEAR SYNERGY 39555823). A publication is not a trial. `harness/identity.py` already builds one identity per trial by union of identifiers (NCT/PMID/DOI/acronym) — the screening/absence/invalidation layers do not use it. Wherever the page says "trial(s)" about a count of records (`harness/page.py:~460, ~965`, `harness/invalidation.py`, the declared-absent tables, PRISMA counts in `harness/manuscript.py`), the count must be of trial families (resolved via `identity.py`), with publication counts stated separately, e.g. "7 further trials (11 publications)".
2. **Served-as-included that should not be:** on colchicine-secondary, an economic COLCOT analysis, a secondary LoDoCo2 publication, and a perioperative cardiac-surgery colchicine study (wrong population — the protocol is coronary disease / recent MI; peri-operative POAF prevention belongs to `colchicine-postop-af`) are screened IN (decision=include). **Served-as-excluded that should not be:** a randomised coronary-colchicine study that an independent model judged eligible is screened OUT. Identify each of these records by PMID from `docs/reviews/colchicine-secondary-cv-prevention/review.json` (`screening` block) and `cache/colchicine-secondary-cv-prevention/records.json`; for each state the record's publication type and its trial family (which pooled trial it belongs to, if any), the screen rule that fired, and what the correct state is: `SECONDARY_PUBLICATION_OF <trial_key>` (linked to the family, NOT counted as an eligible trial, NOT declared absent), `WRONG_POPULATION` (excluded with the rule id), or ELIGIBLE (in which case do NOT pool it — pooling is out of scope — leave it declared-absent with the honest reason and flag it in the report for the integrator). Make the screening state carry `trial_family_id` and `publication_role` (primary / secondary / economic / protocol / correction).
3. **Corpus-wide:** `scripts/publication_unit_sweep.py` over all 32 topics: for every screened-in-not-pooled record, resolve its trial family; report `n records of N` that are secondary/economic publications of an already-pooled trial and were being counted as "trials"; rebuild affected pages; `reproduce_review.py` each; quote the before/after banner and count sentences per page.
4. **Scope drift.** `spironolactone-hfref-mortality` pools RALES (spironolactone), EMPHASIS-HF and J-EMPHASIS-HF (eplerenone). The protocol (`topics/spironolactone-hfref-mortality.json`, `protocols/`) already says "a steroidal mineralocorticoid receptor antagonist, specifically spironolactone or eplerenone"; the page title says MRA; the slug and `identifier_scope` say spironolactone and the page flies `identifier_single_agent_class_pool` BLOCKS_CLAIM. Make the identifier and protocol HISTORY reflect the class review: find how identifier scope is declared (`harness/identifier_scope*`, `topics/*.json` `identifier`/`intervention` fields, `harness/registration.py`) and add the mechanism the codebase uses for a protocol amendment (look for `amendments`, `protocol_history`, `PREREGISTRATION_v2.md`, `docs/provenance.json`) — an APPENDED, dated amendment record "identifier widened from single agent to MRA class; reason; pre-specified list", never an in-place rewrite of the original protocol text. Do NOT rename the slug or URL (the served URL is a pinned identity). Rebuild; the `identifier_single_agent_class_pool` reason should resolve to a disclosed, dated scope amendment rather than a block — or, if the codebase's rule is that a slug/identifier mismatch always blocks, say so and stop; do not weaken the gate to clear the banner.
