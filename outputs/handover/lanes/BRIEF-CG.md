## What to build

`harness/claimgraph.py` (new) plus wiring:

- **One trial identity for every consumer.** `trial_key(trial_dict) -> str` = the identifier in `trial["id"]` (`PMID 39555823` → `39555823`; `NCT02422186` → `NCT02422186`), never `label`. Use `harness/identity.py` if it helps. Fix `rob_sensitivity.sensitivity` to join rob2 by `trial_key`; audit every other place that joins pooled trials to a side table by `label` (grep `label` in `harness/*.py`; `spec_curve.py`, `rob2`, `funding.py`, `armcontrast`, `manuscript.py` are candidates) and list what you found in the report, fixed or not.
- **Input-set version.** For each outcome: `input_set_version = sha256(canonical JSON of sorted [(trial_key, the numeric inputs actually consumed: ai/ci/n1i/n2i or effect/ci_low/ci_high or mean/sd/n, scale)])`. Store on `outcome["result"]["input_set_version"]`.
- **Result/claim IDs with dependencies.** Every result-bearing object gets `claim_id = sha256(kind + outcome name + input_set_version)[:16]` and `depends_on = {"input_set_version": ...}`: primary/secondary results, `rob_sensitivity.{full,drop_high,low_only}`, each strand pool in `review["strands"]`, each refusal row (`docs/refusals.json` entries → typed objects keyed by trial_key + outcome), each declared-absent/membership state row, `grade`, `manuscript` result sentences, and the RoB-sensitivity prose. Objects that are recomputed in-build simply carry the current version; objects loaded from hand registries (`docs/refusals.json`, `docs/parity.json`, `docs/iv_iron_strands.json`) must record which trial_keys they depend on and be checked.
- **Consistency check = `claimgraph.check(review) -> list[violation]`**, run inside `build_review_core` (so `reproduce_review.py` sees it) and as a `harness/gate.py` page check. Violations, each a typed code: `ROB_JOIN_MISS` (a pooled trial rated in rob2 but absent from sensitivity levels), `STALE_DEPENDENT` (an object's `depends_on.input_set_version` ≠ current), `REFUSED_AND_POOLED` (trial_key in a refusal row and in a pooled trial set for the same outcome), `STRAND_OUTSIDE_CLAIMS` (a strand pool with k≥1 not counted in claims / a strand member reported "not pooled in any outcome"), `PROSE_PREDICATE_FALSE` (a rendered predicate whose condition is false of the object — start with the "fewer trials" one and the parity `= our pool` / `= ours` rows whose named trial set ≠ current trial set), `MEMBERSHIP_CONFLICT` (a trial_key both declared-absent for an outcome and pooled in a strand of that outcome).
- **UNRENDERABLE, not flagged.** On any violation the affected object is replaced in the rendered page by a fixed block naming the violation code and the claim_id, with NO numbers from the stale object, and `build_review_core` / `gate.py` REFUSES the page. Not a banner beside the stale number — the stale number must not be on the page.
- **Claims counter scope line.** Replace "Claims checked: N; contradictions caught: M" with the same plus "scope: <kinds checked, counts>; not in scope: <kinds>" derived from the graph, so 0 cannot read as safe.
- Then fix the instances so the pages render again: rob join; strands enter claims and membership; `docs/refusals.json` — remove the Torres row ONLY IF the pooled row is the policy the protocol declares (the primary's `timepoint` is "30-day or in-hospital", Torres is in-hospital → pooled is consistent; the refusal is stale → drop it and record why in the report); the dpp4 predicate; parity text rows for ticagrelor/spironolactone become STALE (do not rewrite their prose to be true — leave them unrenderable and report it; the integrator decides the wording).
