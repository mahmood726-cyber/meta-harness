## The object (`TrialFamily`) — committed per topic as `cache/<slug>/families.json`, consumed by the page
- **Identity**: `family_id` = registry-anchored primary key in priority NCT > EudraCT > ISRCTN > jRCT > other registry; a family with no registry record gets `family_id = "SYN-" + sha256(sorted primary-report ids)[:12]` and `identity_flag: NO_REGISTRY_RECORD`. Aliases kept (`acronym`, all registry ids, all PMIDs/DOIs).
- **Reports** `[{report_id (PMID/DOI/PMC/URL), role, span_basis, retrieved_via}]` with **role ∈ {PRIMARY, SECONDARY_ANALYSIS, SUBGROUP, POOLED_ANALYSIS, EXTENSION, PROTOCOL, SAP, CORRECTION, RETRACTION, CONFERENCE_ABSTRACT, REGULATORY_FDA, REGULATORY_EMA, HTA, REGISTRY_RECORD, DESIGN_PAPER, COST_EFFECTIVENESS, OTHER}**; role assigned from typed evidence (pubtype, title/abstract phrases, registry link, DOI relation) with the span that decided it; `ROLE_UNRESOLVED` when none — never guessed.
- **Arm structure** `[{arm_id, label, drug, dose, schedule, route, background_therapy[], n_randomised, span}]` from AACT `design_groups` + `design_group_interventions` + `interventions` where the NCT is in the snapshot, else from the abstract via the arm object (SC3) with spans; `randomised_contrasts` = the set of arm pairs that differ ONLY in the intervention of interest (drug-of-interest present in exactly one arm of the pair; same background). This is what answers "is the drug of interest what differs between arms" — MIRO-CKD, PYY1875, CRUSADERS, COVID STEROID 2, RECOVERY high-dose all fail it structurally.
- **Population**: entry criteria typed fields from AACT `eligibilities` (age bounds, sex, condition), entry condition, severity/phenotype fields where the protocol declares them; `analysis_sets[]` per report.
- **Per-outcome status** (the dark-evidence ledger; one row per registered review outcome): `prospectively_specified` (from `design_outcomes` primary/secondary + protocol/SAP if held) / `measured` / `reported` (a span exists in any held report) / `extractable` (typed value with span) / `in_primary_pool`; each cell `{state, span|absence_code}`.
- **Lifecycle**: `registered → started → completed → results_posted → publication_found` with dates from AACT `studies`/`milestones`, results tables, and the report set; `entered_via` for the family (`EXECUTED_QUERY(source_id)` / `SEEDED_IDENTIFIER` / `MANUAL_ADDITION` / `LEGACY_UNRECORDED`) from the retrieval ledger.

## Rules enforced by the module (each is a defect found today; each has a plant)
1. **A report is never a trial**: `families(records)` collapses every report into its parent by registry id, DOI relations, acronym + shared arms; a report that cannot be attached becomes its own family flagged `PARENT_UNRESOLVED`. Plants: COLCOT cost-effectiveness paper (colchicine-secondary), LoDoCo2 secondary, STEP 6 post-hoc (PMID 40189961) attaching to its parent, PLATO subgroup papers (ticagrelor), EMPA-KIDNEY post-trial follow-up — each collapses; pre-fix count of PMIDs vs post-fix count of families quoted.
2. **An extension that removes the randomised contrast is not a new comparison**: role `EXTENSION` + `randomised_contrast_preserved: false` (crossover, open-label continuation) → never a pooled row on its own; plants: FREEDOM extension (denosumab), DIRECT 3-year open-label, FREEDOM-CVO is NOT an extension (control).
3. **A family appears once in any count**; the counts render as a chain `publications_screened → trial_families → eligible_families → contributing`; the single "n trials met eligibility" sentence is generated from the chain and cannot be typed.
4. **Eligibility is decided once per family** (SF's `screen_family`) from the arm structure and population fields; reports inherit.
5. Every field has a span or a typed absence; no field is inferred from a name.
