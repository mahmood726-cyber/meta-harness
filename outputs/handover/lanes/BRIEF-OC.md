# LANE OC — odds ratios are not first-event risk/hazard ratios: fix the compatibility class, and check all 64 blinded mirrors

Report file: `LANE-OC-REPORT.md`.

## The failure

`harness/estmeasure.py` maps `ODDS_RATIO` into class `FIRST_EVENT_RATIO` together with `RISK_RATIO` and `HAZARD_RATIO_FIRST_EVENT`. On `corticosteroids-cap-mortality`, Harms tab, outcome *Hyperglycaemia*, the pool is Torres 11/61 vs 7/59 (count-RR 1.52) + Blum 2015 (25608756) published **OR** 1.96 [1.31, 2.93], served as RR 1.88 [0.17, 20.09], compatibility key "Effect-measure labels pooled OR, RR", and the recovery-recheck sentence "Pooled trials report different effect-measure labels (OR + RR), combined as first-event relative ratios. This is an approximation, not an identity: a hazard ratio and a cumulative risk ratio are not the same number…" — the HR/RR template text fired for an OR. Hyperglycaemia is common (≈11–19%), so OR≠RR materially. This contradicts (a) the site's index page and `docs/external_agreement.json._doc`: "an odds ratio sits further from 1 than a risk ratio for common events … comparing them … is comparing different quantities"; (b) `iv-iron-hfref-hosp`, which suppresses a pool across estimand classes; (c) the sentence's own explanation. The served blinded mirror `docs/m/m0594e053/index.html` carries the same text.

## What to build
