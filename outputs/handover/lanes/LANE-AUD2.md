## Defect 5 — assurance counters overstate (confirmed by two independent readers)
On the committed IV-iron review: "claims checked: 4" while actual calls to the cross-surface significance checker = 0; the census sums strand counts without running strand checks and suppresses rendering exceptions while still reporting surfaces as checked; the interval-provenance checker accepted a k=8 result carrying the single-trial token `source-reported-CI:k=1-verbatim`. **Fix**: every check emits a RECEIPT (`{check_id, surface, state: planned|attempted|completed|failed, detail}`); counts are derived from receipts, never from self-reported totals; a checker or renderer exception is `failed`, never `skipped`; every result-bearing surface is traversed; each provenance label's conditions are enforced (`k=1-verbatim` only when k==1; "canonical engine" only when the engine receipt exists). Plants: the IV-iron count (paste "4" pre-fix, the receipt-derived count post-fix), the k=8/k=1 token.

## Defect 6 — GRADE turns missing information into favourable judgements
`{"pico_scoped": true}` alone → `assessed: true`, zero downgrades, 0% unpublished from 0 of 0; imprecision calls HR 0.60–0.99 "precise", assesses MD −10 to −0.01 with no MID, and for HR 0.65–1.00 says both that null-crossing is uncertain by rounding and that the interval excludes the null. **Fix** in grade.py: missing denominators, missing information-size assessment or missing clinical threshold → `NOT_ASSESSABLE` / `REQUIRES_JUDGEMENT` (never a favourable rating); statistical significance alone never establishes decision-relevant precision; a domain assessed from 0 of 0 trials is NOT assessed. Plants: the three cases above pre/post.

## Defect 7 — certificates don't bind what their names imply
`search_completeness` accepted an artefact with no candidate records/sources and counts of 999; changing a rendered independent-extraction tally to 999 altered the HTML but left the evidence certificate unchanged. **Fix**: derive counts from records (a count without its record set is refused); require the source/query/raw-record joins; the certificate binds every rendered evidence object and its scientific dependencies (endpoint, analysis population, censoring, design, estimator — via the existing `input_set_version`/dependency machinery, not a new one). Split the certificate's assurance into four NAMED kinds, each with what it binds: **Integrity** (declared source/output bytes match), **Execution** (the recorded computation ran on the declared inputs; trust model stated), **Semantic compatibility** (typed result + adjudicated interpretation fit this question), **Scientific adequacy** (search, bias, applicability, interpretation have adequate support and review — rendered as the trust inputs with reviewer identity/rationale/scope, never as a hash). A hash establishes identity, not truth — say so in the object. Plants: the 999 tally must change the certificate; the empty-records artefact must be refused.
