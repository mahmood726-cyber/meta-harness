## Test repairs (why each changed)

- **test_bundle_verifier plants re-pinned the way a consistent producer would.** `_recompute_everything`, test_h1 and the two
  direct bundle-edit plants (m11 fragment, unsupported representation) now call `_pin_and_stamp`. It pins the edited bundle's core
  into the certificate, re-releases it, and stamps the release-bound fields. Without this step every doctored-site plant stopped at
  `BUNDLE_DIGEST_MISMATCH` before any row was judged.
- **`POOL_NOT_REPRODUCED` is gone** from the verifier (POOL V1.1). A non-reproducing pool is now named by which declaration it
  disagrees with: `POOL_BUNDLE_RESULT_DISAGREES` or `POOL_CERTIFIED_RESULT_DISAGREES`. The named-codes test lists those. Anything
  downstream matching the old string needs the new names.
- **test_pool_binding's refusal control is built, not borrowed.** It needed "at least one admission-refused row" from the live
  corpus. That was HARMONY, which is now admissible, so the control retired itself (the same defect evid2 fixed in 91f057a4).
  `refused_row_store()` sets HARMONY's certified eligibility to UNKNOWN in an isolated store and re-pins everything a producer
  would: families.json digests, `trial_family_map_sha256`, the rendered copy, the recorded row verdict and the bundle pin. The
  authentic test now asserts PASS with 8 of 8.
- **The 2 reciprocal cases.** Pool inputs are references, so a plant that writes reciprocal values into them is refused
  (`POOL_INPUT_NOT_A_REFERENCE`) *before* any arithmetic. The old assertion `certified_result_agrees is True` belonged to the
  value-carrying design. For these two cases the test now asserts "refused before arithmetic" (`recomputed is None`, guard
  refused). The verifier is unchanged: it fails closed and reports no agreement when nothing was computed.
- Result: `tests/test_pool_binding.py` + `tests/test_bundle_verifier.py`: **103 passed, 4 skipped** (before: 17 failed, 20
  errors). The skips are the pre-existing `f6_repaired.json` NOT-RUN guard.
