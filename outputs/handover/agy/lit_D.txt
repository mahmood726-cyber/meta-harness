1. Unconditional Assertional String Literals in Formatting (f-strings or concatenation):
   - Syntactic Shape: A `JoinedStr` (f-string) or `BinOp` (string formatting/concatenation) containing a `Constant` string node with past-tense action verbs (e.g., "found", "verified", "assessed", "checked", "falsified"). This node is returned or assigned without being nested inside an `If` or `IfExp` conditional that checks a dynamic property of a state object.
   - False-Positive Risk: High, as it will flag legitimate methodology explanations (e.g., "Risk of bias was assessed..."). It requires filtering to target specific declarative narratives or anecdotes (e.g., "this check found", "direct testing falsified").
2. Hardcoded Date/Time Variable Assignment:
   - Syntactic Shape: An `Assign` or `AnnAssign` node where a target `Name` matches a time-related regex (e.g., `(?i)(now|run|generated|retrieved|measured)_(date|time|on|at)`) and the `value` is a `Constant` (string/integer representing a fixed date or timestamp).
   - False-Positive Risk: Medium. Common in mocked test fixtures, so tests must be explicitly excluded.
3. Unconditional Status Constants:
   - Syntactic Shape: An `Assign` or a `Dict` key-value pair where the target or key denotes a state (e.g., `status`, `state`, `result`) and the assigned value is a string `Constant` such as 'verified', 'assessed', or 'PASS', unconditionally set without dynamic derivation.
   - False-Positive Risk: High. Flags common sentinel values or initialization states (e.g., defaulting variables to 'PASS' before validation).
4. Live Time-Stamping in Deterministic Artifacts:
   - Syntactic Shape: A `Call` node invoking `datetime.now()` or `datetime.utcnow()` inside functions meant to generate reproducible outputs (often matching naming patterns like `build_*`, `generate_*`, or `render_*`), instead of consuming a frozen timestamp from a state object.
   - False-Positive Risk: Low if tightly scoped to output generators, but Medium if it flags generic logging decorators.
