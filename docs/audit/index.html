External audit pack: auditor's guide

This pack lets you audit the 32 served reviews of the meta-harness without access to our machines. Everything it refers to is either served on this site or in the public repository https://github.com/mahmood726-cyber/meta-harness. It is generated by scripts/build_audit_pack.py from committed files; nothing in it is typed by hand except this prose.

  • The 32 reviews (22 active, 10 abandoned by decision), with pinned identities.
  • Extraction spot-check sample (40 rows drawn at seed 20261008 from the 103 extracted trial rows shown on the pages' Data extraction tabs).
  • Per-review checklists: checklist/<slug>.html, linked from the review list.
  • Findings template · audit_pack.json (all of the above, machine-readable).

What the harness claims, and what it does not

Claimed. Every served pooled number is computed by committed code from committed inputs, and every extracted trial number shown on a page's Data extraction tab carries the passage it was read from. Each review page names a certificate (CERTIFICATE.json) whose digests cover the protocol, the search record, the screening ledger, the extraction objects, the analysis code and the rendered review; scripts/reproduce_review.py <slug> rebuilds the review offline from the committed cache and fails if any digest or the served page differs. Changes to a served result are published as notices, each countersigned on the exact bytes shown (Changes & signatures tab).

Not claimed. Replay proves the same inputs give the same outputs; it does not prove the inputs are right, that the search found every eligible trial, or that a fresh search today would return the same records. Agreement with a published meta-analysis (the G1 panel) is a comparison, not independent corroboration. Risk-of-bias judgements are the rule-based ratings; the recorded dual-model sign-off required by decision D11 is not yet applied (each page says so). A topic marked ABANDONED_BY_DECISION stays served but is not counted as matched. Each page's Overview lists its own stated limitations.

How to replay any number

  1. Open the review page, tab Data extraction. Each extracted trial number shows its source passage and sha256 of that passage (UTF-8), and the outcome's served state (pooled, single trial, refused). Recompute the digest from the passage; compare the passage with the source record (the PMID links to PubMed; registry ids link to ClinicalTrials.gov or ISRCTN). Outcomes the gate withholds (incomplete harm ledgers, suppressed pools) are named with the reason instead of rows.
  2. For the pooled result: 
    git clone https://github.com/mahmood726-cyber/meta-harness.git && cd meta-harness
python -m pip install --require-hashes -r docs/offline/requirements.lock
python scripts/reproduce_review.py <slug>
    The replay compares review_sha256 (listed per review in reviews.html) and the served page bytes (html_sha256 in each review's manifest.json).
  3. To check a certificate without our code: python docs/scripts/audit_certificate_stdlib.py (standard library only).
  4. Cite review_sha256 in every finding: the page you audited is identified by it, not by its URL.

Provenance types

Every extracted row carries a recorded provenance value (where the value was read: abstract, ctgov_results, fulltext_verified, ...) and a provenance class computed by the gate (harness/provenance_class.py, the same function the page uses):

ClassRows shown on the pages
EXTRACTOR89
HAND_ENTERED4
RECORDED_MODEL_CALL10

EXTRACTOR: a deterministic regex or typed extractor over a held source, with the span it read. RECORDED_MODEL_CALL: a recorded model call that replays offline; its record id (mc-<32 hex>) is in the repository and linked from the row. HAND_ENTERED: entered outside the harness and bound to a held span; allowed only while listed in registry/provenance_hand_entered.json, a list that may only shrink. UNTRACED: refused by the gate (none should appear on a served page).

Known limitations

Each review lists its own limitations (Overview tab, Stated limitations); the per-review checklist links them. Across the corpus, the index page states the selection effect (which pre-registered topics were built) and the honest split of what the external audits found. Topics registered but never served are listed in reviews.html.
